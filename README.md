**冰箱作為量表 · 提案 v4**

**作品簡介（100–200 字，供表單使用，請依實際表單字數限制微調）**

長照失能評估目前依賴到宅問答與家屬代答，受記憶偏誤與家訪當天效應影響。本系統以居家行為觀測（影像、感測器、聲音事件）建立長輩自身的個人基準線，由本地端三個代理人分別負責長輩互動、行為觀測與機構溝通。異常時，系統附上證據與信心度，回報照管中心，供複評與居服派工參考。系統輸出行為代理指標，不做診斷，不自動通報，僅提供證據，由人做判斷。

## 02　問題與核心洞察（沿用 v2 第 02 節，本版無實質修改）

核心洞察不變：

> 量表問的是趨勢，答案卻來自一個瞬間的回憶。問答式評估天生不適合取得趨勢資料，而連續監測正好是為趨勢而生的。這就是整個系統存在的理由。

自述偏誤、家屬代答偏誤、家訪當天效應、點狀取樣、評估者間差異五個問題，以及「更客觀、更連續」而非「更早偵測」的對外主張，詳見 v2 提案第 02 節，內容不變。

## 03　系統架構：Edge 三代理人 ＋ 共享層 ＋ Cloud 派工介面

### 3.1　舊架構對照新架構

三個代理人不是新功能，是 v2 原本 L0–L7 的重新分組。技術判斷全部保留，只是換一種講法：

| v2 原本的層 | 對應到 v3／v4 哪個角色 |
| --- | --- |
| L0 感測層、L1 低成本感知 | 行為觀測代理人（感測輸入） |
| ASR 隔離區 | 照護對話代理人（語音僅在此） |
| L2 事件層、L2b Context Builder | 行為觀測代理人（事件與基準線） |
| L3a Risk Gate | 機構溝通代理人（規則引擎） |
| L3b 行為指標累積、L4b 量表對接 | 行為觀測代理人（產出關鍵警示與行為異常指標） |
| L4a Action Policy | 機構溝通代理人（通知分級） |
| L5 路由與揭露 | 機構溝通代理人 ＋ Cloud 派工介面 |

共享層（見 3.5）是 v4 新增，v2 架構中沒有對應項目，因此不出現在上表——它不是既有功能的重組，是團隊在 v3 之後新提出的角色。

### 3.2　照護對話代理人

對象是長輩本人。長輩主動觸發，或系統依規則判斷資料不足且值得詢問時，以低侵入方式提出一句簡短問題。語音辨識只存在於這個代理人的觸發情境，其餘時間系統不具備語音辨識能力，ASR 為獨立同意項——這條界線與 v2 完全相同，只是現在清楚掛在一個代理人身上，不再只是一句抽象的架構承諾。

產出：經確認的事件記憶、長輩自述補充、提醒回覆。

本版新增：這個代理人的對話紀錄是共享層溝通偏好摘要（見 3.5）的唯一資料來源；摘要結果回饋給這個代理人本身，用於調整下次對話的措辭與敏感度，例如是否適合提起「即期品」這類話題。

### 3.3　行為觀測代理人

對象是住家環境，不對長輩喊話。輸入包含影像（本地 VLM）、感測器訊號、聲音事件分類。聲音處理只做事件分類（例如跌倒聲、流水聲、開關門聲），不做語音轉文字——這條界線與照護對話代理人的 ASR 權限互斥，不共用模型或管線。

產出兩種指標，證據力不同：

- **關鍵警示**：規則明確、證據直接。例如服藥時段內藥盒未觸發、跌倒聲音後一段時間內無後續活動訊號。
- **行為異常指標**：多訊號佐證的相關性指標，附信心度。例如爐具或冰箱使用頻率相對於該住戶自身基準線的偏移。

個人基準線一律以該住戶自身前若干週的資料計算，不使用群體閾值。

本版新增：這個代理人可讀取共享層提供的溝通偏好與基準線，用於排除已知個人習慣造成的誤判——例如向來話少不代表退縮。但回傳給機構溝通代理人的欄位僅限信心度與證據，不得包含偏好內容本身，細節見第 05 節與第 09 節。

### 3.4　機構溝通代理人

對象是機構端。決策邏輯是規則引擎，見第 04 節的具體例子。LLM 的角色僅限於規則觸發後，把結構化結果轉成人看得懂的通知文字，不參與「要不要通知」的判斷。保護性案件不進入這個代理人的自動流程，一律轉人工判斷。每個事件指定唯一責任人，附升級逾時，分級揭露規則沿用 v2 第 07 節。

本版新增：機構溝通代理人不讀取共享層任何內容，這條規則獨立於代理人之間有沒有連接線——真正的防線是行為觀測代理人回傳欄位的內容限制（見 3.3、05、09）。

### 3.5　共享層：基準線與溝通偏好（本版新增，非獨立代理人）

團隊提出的「第 4 個代理人」，拆開來看其實是兩件不同的事，合併討論容易失焦：

**(a) 行為基準線統計** — 就是各代理人本來就需要的「該住戶自身前若干週資料」，獨立出來做成一份共用記錄，讓行為觀測代理人不用每次重算。這不是新功能，是既有需求的重組，只需要聚合統計，不需要模型。

**(b) 溝通偏好摘要** — 從照護對話代理人自己的對話紀錄，萃取可觀察的溝通型態（例如：偏好直接說明或委婉提醒、對「即期品／浪費」相關話題敏感或不敏感），供照護對話代理人下次對話調整用詞，也供行為觀測代理人排除已知個人習慣造成的誤判。這一塊需要真正的推論，不是純統計。

兩者合稱「共享層」，不稱「代理人」——它不主動對外發起任何行動，也不與任何一方對話，單純提供已萃取的資訊供其他角色查詢。稱為代理人會讓簡報多一個要解釋的決策角色；稱為共享層，職責更清楚。

**存取規則（硬性）：**

- 只能讀取行為觀測代理人已產出的結構化事件，以及照護對話代理人自己的文字紀錄——不得直接存取原始影像或原始音訊，維持原始媒體不離開裝置邊界的既有承諾。
- 溝通偏好摘要只能包含可觀察的溝通方式描述（語氣、直接／委婉、對特定話題的敏感度），不得包含心理狀態、情緒或動機的推論字眼——與行為異常指標不得宣稱偵測情緒的原則一致。
- 機構溝通代理人不得讀取這一層的任何內容。這條規則不能只靠「沒有連接線」達成：行為觀測代理人回傳給機構溝通代理人的欄位，必須明訂只有信心度與證據，不得包含偏好內容——否則偏好資訊可能透過異常說明文字間接外洩。
- 使用對話紀錄建立長期溝通偏好檔案，是有別於「即時回答長輩問題」的另一種資料用途，需要在同意書上獨立列出一項，不能沿用既有的 ASR 觸發同意。

**Demo 範圍（功能切片，非完整功能）：**

- 團隊原先舉的例子（提醒即期品）需要先解決「品項辨識＋保存期限追蹤」，這是目前完全沒有著手的獨立難題，本版明確排除，不放入這次 demo。
- 改用不依賴品項辨識的最小切片：錄一段種子對話 → 萃取一到兩項結構化溝通屬性（例如語氣偏好） → 存成本地小型紀錄（不保留原始逐字稿） → 照護對話代理人在既有觸發點（例如冰箱門開啟）依據該屬性調整措辭。
- 台上明講：這是機制的功能驗證，完整的溝通偏好模型是 roadmap，不是這次 demo 的完整成果。

## 04　判斷邏輯：規則引擎與信心分級

### 4.1　關鍵警示：規則引擎範例

規則是寫死的條件判斷，不是模型的自由發揮：

| 情境 | 規則（範例，實際門檻待現場資料調校） | 動作 |
| --- | --- | --- |
| 疑似跌倒 | 偵測到跌倒聲音，且夜間時段起算一段時間內無燈光開關或其他活動訊號 | 觸發緊急等級，通知緊急聯絡人 |
| 疑似漏藥 | 排定服藥時段結束後，藥盒微動開關未觸發 | 通知居服員，下次訪視留意 |
| 長時間無活動 | 連續一段時間無任何感測器活動，且非排定外出時段 | 通知里長或訪視網絡，依 v2 升級逾時規則往上升級 |

門檻數字（時間長度等）是待驗證的初始假設，不是查證過的臨床數字，demo 與簡報上須標明「初始設定值，可調整」，避免被追問數字來源時答不出來。

### 4.2　行為異常指標：信心怎麼算

信心度來自佐證訊號的數量與偏移持續的時間，不是模型自己回報的信心分數。單一夜晚電視開得比較久，信心度低，不觸發任何通知；連續多天爐具與冰箱同時出現異常，信心度提高，才進入派工介面的提示清單。

### 4.3　兩者的差異

| | 關鍵警示 | 行為異常指標 |
| --- | --- | --- |
| 決策方式 | 規則引擎，確定性 | 多訊號加權，機率性 |
| 信心來源 | 規則觸發即視為成立 | 佐證訊號數與持續時間 |
| 可否作為複評證據 | 可，證據鏈明確 | 需搭配人工複核，單獨不足以作為複評依據 |
| 下游用途 | 立即通知、升級 | 派工前參考、提醒訪視留意事項 |

## 05　隱私與資料邊界（對應新架構，底線與 v2 相同，本版新增共享層規則）

- 影像與聲音處理都在行為觀測代理人內部完成，原始檔案不離開裝置邊界。
- ASR 只存在於照護對話代理人的觸發情境，是獨立同意項，與行為觀測代理人的聲音事件分類完全分開，不共用模型。
- VLM 為本地推論。Mac mini M4 是目前的開發與展示機，正式出貨的硬體另外評估，任何段落都不得因為時間壓力而改口為雲端 VLM API。
- 不在浴室與臥室安裝影像感測器，沿用 v2 不變。
- Cloud 端只接收結構化的關鍵警示、附信心度的行為異常指標，以及人工輸入的照顧筆記——不接收原始影像、不接收語音、不做跨住戶比對。
- **（本版新增）**共享層只讀取行為觀測代理人的結構化事件與照護對話代理人自己的文字紀錄，不得直接存取原始影像或音訊。
- **（本版新增）**溝通偏好摘要為獨立同意項（「使用對話紀錄建立長期溝通偏好」），不得沿用既有的對話觸發同意涵蓋長期建檔用途。
- **（本版新增）**機構溝通代理人不得讀取共享層內容；行為觀測代理人回傳給機構溝通代理人的欄位明訂只有信心度與證據，不包含偏好內容——防止偏好資訊透過異常說明文字間接外洩。

## 06　機構端派工介面（草案，待第 08 節決議後細化）

- 使用者：居服員、里長、照管專員，依角色看到不同粒度，分級揭露規則沿用 v2 第 07 節。
- 定位：派工與訪視前準備工具，不是 KPI 儀表板。目的是幫工作人員決定「今天先去看誰、去之前該知道什麼」。
- 畫面上的每一則資訊都標示來源，來源分三類，不可混淆：
  1. **關鍵警示**——來自機構溝通代理人，規則觸發，可回溯到具體事件。
  2. **行為異常指標**——來自行為觀測代理人，附信心度，標示「訪視前參考，非診斷」。
  3. **照顧筆記**——由照服員或家屬人工輸入，例如飲食喜好、日常作息。這類資訊不是系統觀察得來的，是人工建檔，不會因為改天沒人輸入就消失或被系統覆寫。
- 預填複評摘要（v2 第 06 節）服務照管專員，週期以月計；派工介面服務居服員與里長，頻率更高、更即時。兩者並存，對應 v2 第 07 節原本就規劃的不同角色需求。
- **（本版新增）**共享層的溝通偏好摘要不進入這個介面，只供 Edge 端角色內部使用，與第 05 節規則一致。

## 07　Demo 誠實原則與範圍

目前沒有裝設任何實體感測器，所有輸入資料為模擬。現場展示鏈：

    預錄影片（跌倒／日常行為） → 現場即時 VLM 推論（每一幀都實際運算，輸出不得預先寫死）
      → 規則引擎判定 → 機構溝通代理人 → 派工介面／複評摘要更新

歷史基準線資料以模擬方式產生，並在畫面與簡報上明確標示為模擬，用來展示行為異常指標的信心度如何隨資料量增加而提高。模擬資料須刻意包含一段「不可觀測」區間（例如感測器離線或長輩外出探親），用來展示系統不會把「不可觀測」誤判成「無事件」——這是 v2 三態設計的原始用意，本版沿用。

即時攝影機是加分項，只有在預錄影片鏈路完全穩定之後才嘗試，不能為了追加即時鏡頭犧牲預錄鏈路的穩定性。需準備錄影備援，現場優先使用真推論，備援僅在意外時使用。

上台時必須主動說明哪些是即時真推論、哪些是模擬歷史資料，不能讓評審自己發現落差——這是 v2 就定下的規矩，本版重申。

**（本版新增）**溝通偏好摘要的展示範圍另見第 3.5 節，是獨立於主展示鏈的一個小切片，不納入上述跌倒／喝水／複評摘要主線，兩者不要在台上混著講。

## 09　不可跨越的界線（對應新架構，重申）

1. 系統輸出行為代理指標，不是量表分數，不是診斷——適用於行為觀測代理人的所有輸出與派工介面上的顯示文字。
2. 保護性案件不自動通報，必經人工判斷——機構溝通代理人的規則引擎明文排除這類案件的自動動作。
3. 持續感知不具備語音辨識能力，ASR 只在照護對話代理人的觸發情境存在，且為獨立同意項——行為觀測代理人的聲音處理禁止導入任何語音轉文字模型。
4. VLM 為本地推論，任何段落不得出現雲端 VLM API 的成本或流程——約束行為觀測代理人的影像模型執行位置。
5. 不在浴室與臥室安裝影像感測器——行為觀測代理人的視野邊界。
6. 個人基準線一律以該住戶自身的過去為比較對象——行為觀測代理人計算行為異常指標時的硬性規則。
7. 每個事件指定唯一責任人，並附升級逾時——機構溝通代理人的通知邏輯。
8. 溝通偏好摘要只能描述可觀察的溝通方式，不得包含心理狀態、情緒或動機推論——約束共享層的輸出內容。
9. 機構溝通代理人不得讀取共享層內容；行為觀測代理人回傳給機構端的欄位僅限信心度與證據——約束跨代理人的資料流，防止偏好資訊間接外洩。

趕時間不是放寬以上任何一條的理由，這句 v2 寫過的話，本版原文保留。
